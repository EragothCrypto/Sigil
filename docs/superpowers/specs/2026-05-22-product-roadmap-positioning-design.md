# Product Roadmap Positioning Design

## Goal

Update Sigil's roadmap so future work reinforces one clear product promise:

> Understand wallet and transaction risk before you sign.

## Core Product Shape

Sigil should stay focused on security decisions around crypto activity. It should not become a broad Web3 chatbot, portfolio app, trading assistant, or compliance suite before the daily user workflow is excellent.

The product should organize around four pillars:

- Scan: transaction scanner, contract risk scanner, pasted payload analyzer.
- Inspect: approval inspector, site reputation, dApp session summaries, wallet exposure.
- Monitor: Wallet Risk Monitor for saved public wallets and watched addresses.
- Decide: Security Decision Assistant for transaction, approval, contract, and wallet-risk questions.

## Premium Direction

Sigil Wallet Monitor should be a premium feature inside Sigil, not a separate app.

Free users can scan a limited number of addresses or payloads per day. Paid users get persistent wallet monitoring, higher limits, exposure summaries, alerting, and a prioritized "fix this first" checklist.

## Assistant Boundaries

The assistant should answer only security and transaction-decision questions:

- Should I sign this transaction?
- Is this approval risky?
- What does this contract do?
- Is this wallet exposed?
- What should I revoke first?

It should not answer investment, trading, token-picking, tax, or general Web3 questions.

## Roadmap Impact

The roadmap should place consumer trust and daily utility before API monetization:

1. Finish standalone web app and Chrome extension polish.
2. Build Wallet Monitor as the premium upgrade.
3. Add Security Decision Assistant inside existing result surfaces.
4. Introduce pricing and account features only when the premium value is visible.
5. Add API/team products after consumer retention and signal quality are proven.
